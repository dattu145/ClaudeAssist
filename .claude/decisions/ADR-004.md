# ADR-004: SQLite for Phase 1 persistence

## Status
Accepted

## Context
The controller runs as a single process on a single dev machine. There is one
writer. No multi-host access is needed in Phase 1.

## Decision
Use SQLite (via a well-maintained TS driver, e.g. `better-sqlite3`) for all
Phase 1 persistence, accessed exclusively through repository interfaces
(`ProjectRepository`, `SessionRepository`, `TaskRepository`, `EventRepository`,
`PairingRepository`) defined in `packages/shared`. Use a migration tool (not
hand-run DDL) from day one.

## Consequences
- Zero external infra to run/operate for a single-user local daemon.
- Repository interfaces mean a future Postgres implementation is a new
  adapter, not a rewrite of domain/orchestration code.
- Single-writer model is fine for Phase 1's single-controller-process design;
  revisit only if multi-controller/multi-user (out of scope) is built later.
