# ADR-001: The mobile app does not directly control Claude Code

## Status
Accepted

## Context
Claude Code runs on the user's development machine/server. The Android app
cannot spawn or manage OS processes on that machine, does not have filesystem
access to the projects, and should not hold Anthropic credentials.

## Decision
The mobile app talks only to the local ClaudeOps Controller over REST/WS. All
process/terminal management and all direct `claude` CLI invocation lives in the
controller. The mobile app has zero knowledge of how a session is actually run.

## Consequences
- Mobile app is a thin, replaceable client — the same command surface will
  later serve voice, WhatsApp, and web clients without controller changes.
- Requires the controller to be reachable from the phone (LAN today; a secure
  tunnel/remote-access story is a later-phase problem, explicitly deferred).
- All security/auth boundaries concentrate in the controller (pairing, see
  SECURITY.md) rather than being split across two runtimes.
