# ADR-005: Voice is separated from the command layer

## Status
Accepted

## Context
The long-term product routes voice, mobile UI, WhatsApp, and Bordio-triggered
actions all into the same underlying operations (get status, send instruction,
resume, stop). Building voice-specific plumbing into the controller now would
couple the core system to an unbuilt, unresearched capability
(research/android-background.md, research/voice.md are stubs).

## Decision
All Phase 1 commands go through a single typed command surface (REST/WS +
internal `CommandRouter`). `IntentResolver` is defined as an interface only —
no LLM-backed implementation ships in Phase 1. Voice, when built, will produce
the same `Intent` + `Target` + typed payload that mobile UI actions already
produce, and will call the same controller endpoints.

## Consequences
- Voice work in a later phase is additive (new intent-resolution front end),
  not a controller rewrite.
- Forces Phase 1 command design to be source-agnostic (`source` field on
  events/commands rather than mobile-specific assumptions) from the start.
