# ADR-002: The controller starts as a modular monolith

## Status
Accepted

## Context
Phase 1 needs project/session/task registries, an event bus, REST/WS APIs, and
a Claude Code adapter. The long-term product adds voice, WhatsApp, Bordio,
multi-user permissions, and orchestration — real future complexity.

## Decision
Ship one Node/TypeScript process with clearly separated internal modules
(domain/adapters/api/orchestration, see ARCHITECTURE.md) communicating through
in-process interfaces and an in-process typed event bus. No message broker
(Kafka/Redis), no service split, no container orchestration in Phase 1.

## Consequences
- Fast to build, easy to reason about, easy to run 24/7 on a single dev
  machine — matches the actual Phase 1 deployment target.
- Module boundaries (interfaces for repositories, adapters, notification
  providers) are drawn now specifically so a future extraction into separate
  services, if ever needed, is a refactor of implementation, not of the public
  contracts. This is the scalability hedge the spec asks for without paying
  the operational cost of distributed systems today.
- Revisit only if a concrete requirement (e.g. multi-host, multi-tenant) makes
  a single process insufficient — not preemptively.
