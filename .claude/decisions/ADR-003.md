# ADR-003: Use the Claude Code CLI's supported flags instead of terminal automation

## Status
Accepted

## Context
See research/claude-code.md. The installed Claude Code CLI (v2.1.266) exposes
`--bg`/`agents --json`/`-p --output-format stream-json`/`--session-id`/
`--resume`/`stop`/`logs`, all scriptable without a TTY.

## Decision
`ClaudeCodeAdapter` is implemented entirely via `child_process` invocations of
the `claude` CLI using these documented flags and by parsing stream-json
output. No screenshotting, no keystroke injection, no Playwright/terminal
emulation is used to control or read Claude Code sessions the controller
manages.

## Consequences
- Robust to Claude Code UI changes (a text/terminal-rendering change doesn't
  break the adapter, since we never parse rendered terminal output).
- Cannot send instructions into a session the user started interactively by
  hand outside ClaudeOps — documented as a limitation
  (research/claude-code.md), not solved with a workaround. Read-only discovery
  of such sessions via `claude agents --json` is still possible.
- Adapter must re-verify flag availability against `claude --version` on
  startup (via `claude doctor`/`--version` check) since this is an evolving
  CLI surface.
